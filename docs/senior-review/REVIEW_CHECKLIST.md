# 시니어 과정 공통 코드 리뷰 체크리스트

각 항목은 `통과`, `수정 필요`, `해당 없음` 중 하나로 평가하고 근거 파일과 재현 순서를 적습니다.

## 공통 품질

- [ ] 설명과 예제 코드의 내용이 일치한다.
- [ ] 시작 파일과 완성 파일이 문서의 명령으로 실행된다.
- [ ] 개선 전 코드는 위험을 과장하거나 잘못 가르치지 않는다.
- [ ] 개선 코드는 복사 가능한 예제인지 개념용 의사 코드인지 구분한다.
- [ ] 정상·경계·실패 테스트가 포함된다.
- [ ] 설계 선택의 장점뿐 아니라 비용과 대안도 설명한다.
- [ ] 실제 운영 비밀정보나 개인정보가 포함되지 않는다.
- [ ] 초보 과정과 중복되지 않는 시니어 수준의 판단 과제가 있다.

## React

- [ ] 컴포넌트 분리 기준이 파일 길이가 아닌 책임과 변경 이유에 기반한다.
- [ ] 파생 상태, 비동기 경쟁, 렌더링 병목 설명이 정확하다.
- [ ] 접근성·오류 복구·코드 분할과 테스트 전략이 연결된다.
- [ ] 성능 수치는 재현 조건, 반복 횟수와 한계를 함께 표시한다.

## Supabase·RLS

- [ ] UI 제한과 데이터베이스 권한을 명확히 구분한다.
- [ ] `USING`과 `WITH CHECK`, 소유권, 관리자 상승 차단을 검증한다.
- [ ] service role 키를 브라우저 또는 Git에 넣지 않는다.
- [ ] 역할×행동×소유권의 거부 테스트가 포함된다.
- [ ] Security Definer, Storage, Auth redirect 설명에 우회 가능성이 없다.

## 결제

- [ ] 브라우저 금액을 신뢰하지 않고 서버에서 가격을 다시 읽는다.
- [ ] 중복 주문·승인·웹훅에 대한 멱등성 근거가 있다.
- [ ] 외부 승인 성공 후 내부 저장 실패 복구를 설명한다.
- [ ] 취소·환불·수강권 상태를 분리해서 다룬다.
- [ ] 테스트 결제와 실제 결제를 명확히 구분한다.
- [ ] 카드정보, 전체 토큰과 비밀 키를 로그에 남기지 않는다.
