# 실무 JavaScript 완성 과정 — 강사용 수업 지도서

> 과정 전체 30회차를 실제 수업처럼 진행하기 위한 지도서입니다. 수업 전에 예제와 다운로드 파일을 직접 실행하고, 실제 소요 시간과 반복 질문을 기록합니다.

## 공통 운영 원칙

- 완성 코드를 먼저 보여주지 않고 학습자가 실행 결과를 예상하게 합니다.
- 오류가 발생하면 대신 고치기 전에 첫 오류 문장, 파일, 줄 번호, 재현 순서를 말하게 합니다.
- 빠른 학습자에게는 경계값 실습을, 늦은 학습자에게는 최소 완료 범위를 제공합니다.
- 실제 개인정보·비밀번호·API 비밀 키를 실습에 사용하지 않습니다.
- 회차가 끝나면 예정 시간, 실제 시간, 완료 인원, 반복 질문과 수정 사항을 기록합니다.

## 1회차 · 값과 변수 · 개념 이해

- 주차: 1주차
- 예정 시간: 50분
- 학습 목표: 값과 변수의 역할과 필요한 이유를 설명합니다.
- 완성 결과: 값과 변수 개념 이해 결과물

### 강사가 말할 핵심 설명

const와 let의 용도를 구분하고 변경되지 않는 과정명을 const로 선언합니다. 먼저 강사가 예상 결과를 말하지 않고 수강생이 실행 전 결과를 예측하게 합니다.

### 수업 진행

- **0~5분** 지난 회차 확인과 오늘 만들 결과 소개
- **5~15분** 값과 변수 · 개념 이해 핵심 개념을 쉬운 예로 설명
- **15~35분** 예제 실행 후 내 프로젝트에 맞게 수정
- **35~45분** 오류 해결과 PC·모바일 결과 확인
- **45~50분** 확인 문제, 과제 안내, 학습 완료 표시

### 시연 코드

```text
const courseName = '실무 JavaScript'
let completed = 0
completed += 1
console.log(courseName, completed)
```

### 실습 진행 순서

1. 1회차 시작 JavaScript 파일을 내려받습니다.
2. const와 let의 용도를 구분하고 변경되지 않는 과정명을 const로 선언합니다.
3. TODO 위치를 직접 완성하고 콘솔에서 실행합니다.
4. 정상값과 경계값을 각각 한 번씩 확인합니다.
5. 완성 파일과 비교하고 입력·처리·결과를 설명합니다.

### 정상 실행 결과

1. 과정명과 완료 수가 출력됩니다.
2. 재할당이 필요한 값에만 let을 사용합니다.

### 자주 발생하는 오류와 대응

1. 콘솔의 첫 번째 오류 문장과 줄 번호를 확인합니다.
2. 변수명·괄호·따옴표의 짝을 위에서부터 확인합니다.
3. 입력값의 자료형과 예상값을 console.log로 비교합니다.

### 확인 질문과 정답

1. **질문:** 값과 변수이(가) 필요한 이유를 설명할 수 있나요?
   **정답 예시:** 값과 변수 · 개념 이해의 핵심 목적과 화면에서 맡는 역할을 자신의 말로 설명하면 됩니다.
2. **질문:** 예제에서 직접 바꾼 부분은 무엇인가요?
   **정답 예시:** 예제의 제목·문구·숫자·조건 중 하나를 바꾸고 화면 변화를 확인합니다.
3. **질문:** 완료 결과를 어떤 방법으로 확인했나요?
   **정답 예시:** 브라우저 화면보다 터미널과 개발자 도구에 표시된 첫 번째 오류 문장을 먼저 확인합니다.

### 완료·평가 기준

1. 3점: 회차 기능이 오류 없이 실행됩니다.
2. 2점: 입력·처리·결과를 구분합니다.
3. 2점: 정상값과 경계값을 검사합니다.
4. 2점: 원본 값을 예상치 않게 변경하지 않습니다.
5. 1점: 실행 결과와 수정 내용을 기록합니다.

- **0~5분** 지난 회차 확인과 오늘 만들 결과 소개
- **5~15분** 통합 도구와 품질 점검 · 내 프로젝트 적용 핵심 개념을 쉬운 예로 설명
- **15~35분** 예제 실행 후 내 프로젝트에 맞게 수정
- **35~45분** 오류 해결과 PC·모바일 결과 확인
- **45~50분** 확인 문제, 과제 안내, 학습 완료 표시

### 시연 코드

```text
const normalize = value => value.trim().toLowerCase()
const search = (items, query) => items.filter(item => normalize(item.title).includes(normalize(query)))
console.log(search([{ id: 1, title: 'JavaScript 실무' }], 'script'))
```

### 실습 진행 순서

1. 30회차 시작 JavaScript 파일을 내려받습니다.
2. 검색·필터·저장 함수를 조합하고 정상·빈 값·손상 저장값을 점검합니다.
3. TODO 위치를 직접 완성하고 콘솔에서 실행합니다.
4. 정상값과 경계값을 각각 한 번씩 확인합니다.
5. 완성 파일과 비교하고 입력·처리·결과를 설명합니다.

### 정상 실행 결과

1. 검색 결과 한 개가 출력됩니다.
2. 빈 검색어와 결과 없음도 검사합니다.

### 자주 발생하는 오류와 대응

1. 콘솔의 첫 번째 오류 문장과 줄 번호를 확인합니다.
2. 변수명·괄호·따옴표의 짝을 위에서부터 확인합니다.
3. 입력값의 자료형과 예상값을 console.log로 비교합니다.

### 확인 질문과 정답

1. **질문:** 통합 도구와 품질 점검이(가) 필요한 이유를 설명할 수 있나요?
   **정답 예시:** 통합 도구와 품질 점검 · 내 프로젝트 적용의 핵심 목적과 화면에서 맡는 역할을 자신의 말로 설명하면 됩니다.
2. **질문:** 예제에서 직접 바꾼 부분은 무엇인가요?
   **정답 예시:** 예제의 제목·문구·숫자·조건 중 하나를 바꾸고 화면 변화를 확인합니다.
3. **질문:** 완료 결과를 어떤 방법으로 확인했나요?
   **정답 예시:** 브라우저 화면보다 터미널과 개발자 도구에 표시된 첫 번째 오류 문장을 먼저 확인합니다.
